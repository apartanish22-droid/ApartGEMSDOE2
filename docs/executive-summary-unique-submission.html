Hypothesis — H-RAD-MAG-CONTRAST

Layers: radiometric anomaly gradient, magnetic gradient magnitude, surface conductance proxy (derived from competition feature bands 1–19 when data is present).

Physical signature: concealed geothermal faults lacking surface scarps but hosting hydrothermal alteration that enriches potassium / depletes thorium (radiometric gradient) and demagnetizes host rock (magnetic gradient). The product of the two normalized gradients targets subsurface fluid pathways.

Why it catches catalogue-missing faults: buried / alluvial-covered faults control radiometric and magnetic alteration halos without requiring a visible scarp or catalogue trace.

How it differs from all prior work in this repo: H1 uses radiometric × DEM curvature (surface-expression dependent); dotted-ridge/scarp families use gradient-magnitude edge detection; AP-1 uses geodetic strain × conductance × gravity; UDSR uses updip advection; catalogue-distance uses known faults. H-RAD-MAG-CONTRAST is the first radiometric×magnetic gradient-product lane.

Named non-fault mimics: uneven crustal radioactivity / igneous-contact boundaries (radiometric gradients without faults); mafic/ultramafic contacts (magnetic gradients without faults).

04 / Step-by-step: how to submit

Making a submission into the contest

  1. Download the TIF file above (or the ZIP bundle containing it).
  2. Go to the DrivenData GEMS competition submission page: competition page ↗.
  3. Click "New submission" and choose the downloaded .tif (or .zip) file.
  4. Enter a submission name (unique, e.g. the file stem above).
  5. Enter a short note (≤140 characters) to help tell submissions apart, e.g. clustering with k=25 style.
  6. Click Submit. Save the submission-page receipt and the file SHA-256 together.

Format requirements: single-band GeoTIFF (.tif) or .zip containing one GeoTIFF; must match CRS (EPSG:32611), shape (3730×3292), and geotransform; predicted values must be in range [0, 1].

Known portal error: "Predicted values must be in range [0, 1]" — this file is guaranteed finite in [0,1] across the whole array (zeros outside footprint), which avoids sentinel/NaN/out-of-range causes.
