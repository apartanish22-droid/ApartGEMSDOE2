## 3. Why did GEMSDOE32's submission score highest? (PhD-level assessment)

The name `h33-h33-2-b2-20261004T220000Z-e5eb6e7e-zeros` tells the story:

1. **`-zeros` suffix** — values outside the study footprint are set to 0 (not NaN, not garbage). The Tversky/DTI metric penalizes false positives; zeroing outside the footprint removes FP penalty in non-study areas. This is a free, legitimate score boost.
2. **`h33` dotted family** — GEMSDOE28/29/31 show the same family (h27/h32/h36/h38 dotted-ridge, h33 tip/stepover). Dots placed along ridge tips / fault stepovers / blind fault extensions act as a *recall* device: with the 300 m triangular dilation kernel used in pooled DTI (alpha 0.2, beta 0.8), any dot within ~300 m of a true fault counts as a hit. Beta=0.8 weights false negatives heavily, so over-dotting near plausible fault trends pays off.
3. **Blind faults missing from the catalogue** — dotted tips/stepovers target faults the USGS/INGENIOUS catalogue does not trace (no surface scarp), which is exactly where leaderboard points live.
4. **Thresholded probability maps** — several GEMSDOE submissions are thresholded UNet/sigmoid maps (`-nan` variants), which suppress low-confidence FP.

**Verdict:** 0.2778 is a credible, explainable score — not a fluke — but it is far from the 0.4413 leaderboard high, so there is clear headroom.

## 4. Can we generate a submission scoring higher than 0.2778?

Yes — by being *contrarian but smart*: every focus-family submission is some combination of (a) dotted ridge/scarp lines, (b) DEM openness/relief, (c) catalogue-distance, or (d) Poisson/random dots. None, to our knowledge, combines **geochemistry/radiometry + structural curvature** on concealed faults.

Our unique hypothesis **H1** (below) targets exactly the gap: blind geothermal faults with no scarp but a radiometric + curvature-convergence signature. It is:
- **Unique** — not an exact duplicate of any GEMSDOE site submission (verified by design: different layers, different operator, different name).
- **Format-safe** — single-band float32 GeoTIFF in [0,1] matching the reference grid spec (EPSG:32611, 100 m).
- **Not yet scored** — holdout DTI cannot be computed until real data is in `data/` (blocker, §6). The generated TIF is **NOT OK to submit** in its current demo-grid form.

## 7. How to generate and submit (site-ready steps)

1. **Download data** (authenticated machine): `bash scripts/download_competition_data.sh` → place files in `data/`.
2. **Validate grid:** `python scripts/prepare_data.py` → writes `data/grid_reference.json`.
3. **Generate unique submission:** `python src/generate_submission.py` → writes a unique `assets/gems-h1-*.tif` (+ stable `assets/submission.tif`).
4. **Validate before submitting:** `python src/validate_submission.py assets/<name>.tif` → all gates must PASS (single band GTiff, CRS/shape/transform match, no NaN inside footprint, values in [0,1]).
5. **Holdout gate (mandatory):** run `src/evaluate_holdout.py`; only submit if holdout DTI + 95% CI beats the current best (protocol rules 3–5). Negative results are deliverables — do not spend a slot on an unvalidated idea.
6. **Submit on DrivenData:** single-band GeoTIFF (or .zip of one), unique file name, short note ≤ ~140 chars, values in [0,1], matching CRS/shape/geotransform.
