Automated release checklist for a future candidate

  1. Confirm authorization in machine-readable evidence. The current run card must say verdict: promote, contain a real candidate path and SHA-256, and record a verified selector decision. The current card is negative; stop.
  2. Pass the scientific protocol. Use an explicitly assigned method lane, the canonical repaired shared evaluator/writer, feature-by-feature leakage canaries, a buffered whole-segment holdout, paired uncertainty-aware comparison against a frozen same-protocol best, and the complete registry check before placement and on final dots.
  3. Validate exact saved bytes. Compare the single-band GeoTIFF against an authenticated organizer sample, checking CRS, shape, affine transform, footprint, in-footprint finite values in [0,1], masks/nodata, exterior representation and self-contained bytes. Record SHA-256. A local PASS is not portal acceptance.
  4. Use only the approved manifest values. After every gate passes, the candidate's exact download path, unique name, ≤140-character note, and checksum must come from the current positive run card. Do not copy metadata from an archived card. There is no approved path, name or note today.
  5. Check the live rules and allowance. Consult the official competition page and authenticated submission page for current file rules and weekly allowance. This sandbox cannot verify the live quota or portal behavior.
  6. Upload only after machine approval. Select the exact approved file, enter the generated note, and preserve the organizer's submission receipt with the file checksum. No portal upload or slot was used in this review; this repository does not implement authenticated submission automation.
