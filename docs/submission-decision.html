6. Irregularities flagged for review

  1. Literal lattice gate is not chance-informative. The synthetic 5-px calibration lattice (r13-lattice-s5, 206,895 dots) covers 99.1% of the H-RIDGE3 dots and 99.9% of each site best, while random placement at that density gives about 68%. Excluding it is a user decision, and I have not done it silently.
  2. Registry contains identical bytes under different sites. 13 duplicate-byte groups in the 471-raster focus registry. For example, the GEMSDOE25 best has byte-identical copies filed under GEMSDOE24 and GEMSDOE32, and the GEMSDOE27 best is byte-identical to a GEMSDOE28 file.
  3. GEMSDOE25 and GEMSDOE30 share an identical dot set. Both report 0.2600. I measured identical dot masks (44,090 cells, equal values). The byte hashes differ.
  4. Mirror sample is not the official sample. The owner-mirror sample_submission.tif contains 60,988 ones that match the catalogue labels exactly. The official problem page describes the sample as predicting total fault absence.
  5. Owner mirrors are not organizer data. The competition inputs come from a third-party GitHub mirror of a login-walled DrivenData file. Hash pins prove mirror consistency only. Check the redistribution terms against the DrivenData rules before relying on these bytes.
  6. Extended registry not verified. 89 of its 560 entries use short commit references, which the repo's immutable-SHA rule rejects. The complete registry is therefore not verified.
  7. Conservative local checker disagrees with the official text. scripts/check_submission.py requires every stored cell to be finite, so it rejects the NaN-outside variant. The official text allows NaN outside the bounds.
  8. Zeros twin is not official-format. The zeros-outside twin stores 0 outside the footprint. check_submission.py reports that the outside cells are not null or NaN, so the official rule fails. Use the NaN-outside file, not the zeros twin, if a file is ever cleared.
  9. Off-grid test raster excluded. GEMS36_FORMAT_TEST_NOT_SUBMISSION.tif (32×48) cannot be compared cell-for-cell and is recorded as excluded.
  10. User-reported leaderboard figures do not match the live page. 0.3195 and 0.4413 were reported by the user; the public page shows 0.4544 at #1. See section 2.
  11. User-reported file names do not match the bytes. 5 of the nine site bests are named -nan by the user, but their registry bytes have no NaN cells (zeros outside the footprint). The portal may therefore have received a different file than the one we audited. Settling this needs the exact file you uploaded.

7. What is needed before any file can be cleared

  1. A decision on the literal lattice gate. Either exempt the synthetic calibration raster with a written reason, or change the rule.
  2. A whole-segment, buffered holdout with features built only from visible faults, and a leakage canary for each feature.
  3. A new candidate that beats a frozen holdout baseline with a positive paired interval.
  4. Organizer-authenticated input data (downloaded by you from DrivenData, hash-checked).
  5. The exact rejected file from the portal error, so the [0, 1] cause can be settled.
