The current decision

Why are we stopped?

  1. The prompt refers to an assigned single-method lane, but does not identify one. A parallel branch self-selected AP-1 and reported three runs; its archival record cannot establish external assignment. The complete registry and a locally replayable cache are not present here.
  2. A directly checked, pinned registry lattice covers all but 6,649 cells of the owner-mirror footprint within three pixels. At the usual 37,654 distinct-dot budget, at least 82.34% must overlap; the permitted maximum is 70%. This is a geometry bound, not a score, and assumes that specific footprint. Our read-back found the parallel AP-1 file itself at 99.72% against that witness, so it fails.
  3. The mirror labeled as the sample template has 60,988 positive cells and matches the mirrored fault labels inside its footprint. The official description says the sample predicts total absence. The mirror is not authenticated and must not be treated as the official template.

Using fewer dots is not automatically valid or scientifically justified; shifting points into lattice holes would merely evade the rule. Read the exact-byte audit ↗

Automated project checks

What the site can—and cannot—validate

The repository includes an automated read-back diagnostic for band count, float type, grid, masks, finite values and range. It checks both the published null/NaN exterior wording and a stricter whole-array finite-range diagnostic. A single TIFF must not rely on a separate mask sidecar. The diagnostic cannot authenticate its template, establish holdout performance, test a complete registry, or authorize a slot.

The historic GEMSDOE32 all-finite variant passes the strict whole-array range diagnostic but has unmasked zeros outside the mirror footprint; it fails the exterior check under that mirror and is not approved. We cannot diagnose the user's earlier portal rejection without the actual rejected file and organizer response. Portal acceptance of any encoding remains unverified.

Only after the gates pass

How to make a submission

  1. Verify enrollment and the current rules, deadline, and remaining weekly quota on the competition page. The official rules state a limit of three submissions per week; the current account quota is not visible here.
  2. Only under a newly authorized experiment budget, use the project after an explicit lane, authenticated organizer data/template, full registry and shared tools are available. Run the feature-only leakage canaries, buffered whole-segment holdout, paired comparison to the current same-evaluator best, both novelty checks, and saved-byte format checks. No manual image inspection substitutes for these checks.
  3. A separate selector must approve a weekly slot. Only then will a uniquely named, verified single-band GeoTIFF and a short note be published. No file is approved now.
  4. On DrivenData, sign in, open the challenge, choose Submit → Make new submission, select the approved .tif (or a ZIP containing exactly that TIFF), paste its note, and submit. Record the organizer's receipt and file hash. Never resubmit a historic reference as a new experiment.
  5. Before the deadline select one submission for both prize rounds, and retain reproducible code, data provenance and the required generative-AI disclosure. The official rules govern eligibility and final materials.
Published format

GeoTIFF checklist

  • One float32 band in EPSG:32611, at 100 m, matching the authenticated template's shape, bounds and geotransform.
  • Predictions within the valid footprint must be finite and in [0, 1]. The problem page says data outside bounds is null or NaN; our project separately flags any non-finite stored value because the observed portal error's cause is unknown.
  • Read back the exact saved bytes. A SHA-256 is an identity, not proof of scientific novelty. A successful local format check is not organizer acceptance.

The rules PDF's general appendix mentions 5 p.m. ET, while the competition page currently lists 11:59 p.m. UTC on December 3, 2026. Check the current official deadline rather than relying on either snapshot alone.
