What happens when a candidate clears the gates?

  1. Prerecord the explicitly assigned method, feature sources, non-fault mimic, budget and immutable registry snapshot. Stop if the surface exceeds the specified correlation or proximity threshold.
  2. Once the canonical evaluator is fixed and pinned, run the shared holdout with whole buffered withheld segments. Rebuild every catalogue-derived feature from visible faults only; mask visible catalogue pixels exactly. Test each feature individually for leakage.
  3. Compare pooled HOLDOUT-DTI and its spatial-block 95% confidence interval against a frozen same-protocol best. Do not turn the proxy into a leaderboard forecast.
  4. Check final dots against all registry entries. Once its probability-binarization defect is fixed upstream, use the shared writer and re-open the saved bytes against an authenticated competition template: single float32 GeoTIFF, matching CRS, dimensions and transform; finite values in [0,1] inside the footprint; null/NaN outside as stated by the organizer.
  5. Have a separate automated selector verify the evidence and the current authenticated weekly allowance. Only after approval should the site expose one clearly named download and a note of at most 140 characters.
  6. On DrivenData, select that exact file, paste its note, and submit only if the selector has approved it. Save the organizer receipt and file SHA-256 together. This project does not automatically spend a slot.

These are future steps, not a claim that the current checkout implements a complete training or release pipeline. The official rules PDF states three submissions per week; the authenticated submission page is the authoritative current allowance.

Why is this run blocked?

  • No single method lane was explicitly assigned in the supplied prompt. A parallel session self-selected AP-1, which is not a user assignment.
  • The full shared registry and prepared feature stack are not verified here. The parallel holdout/control comparison was not independently replayed and uses different refill rules for candidate and control.
  • One registered lattice proves that a 37,654-dot candidate must overlap at least 82.34% within 3 pixels. The literal limit is 70%. This is a conditional geometry bound, not a result for every smaller candidate.
  • The public mirror called sample_submission.tif contains 60,988 positive pixels identical to the mirrored labels; the official page describes the sample as predicting total absence. The mirror is not organizer-authenticated.
  • The shared split has no verified 15-pixel truth-to-visible buffer: 15,705 / 22,232 withheld occurrences are within that distance. The prior H-TRACE surface check also happened after placement, and the shared registry auditor is fail-open (issue #63).
  • The shared validator's grid-match label does not authenticate source origin. The pinned reproducible ambiguity was reported to the canonical maintainers; this account cannot push there.

About the range error

The reported message “Predicted values must be in range [0, 1]” is real, but the rejected bytes are not present here, so its cause is unknown. Negative sentinels such as -9999, infinities, values outside the range, NaNs inside the footprint, or incompatible mask/nodata handling are possibilities—not a diagnosis.

The published format requests null or NaN outside the bounds; some older all-finite files use zeros outside. We cannot infer which representation the live portal accepts from a local diagnostic. Do not blindly clip values or change the exterior to claim a fix. Validate the exact saved file against the authenticated template and retain the portal receipt.
