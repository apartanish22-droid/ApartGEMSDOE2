# H2 texture hypothesis — proposal, not a validated result

**Status:** the existing H2 TIFF is a seeded pseudo-feature demo, not an
experiment on competition data. It fails the mirrored-footprint mask and literal
lattice checks. **Do not submit it.** The earlier score ranges and claims that
this file was unique or ready to upload are withdrawn; see the
[saved-byte recheck](../evidence/h2_saved_byte_recheck_20261028.json).

A *future*, separately assigned experiment could ask whether **directional,
multi-scale texture** from a bare-earth DEM, GeoDAWN magnetics and available
radiometric bands adds evidence for a continuous, previously unmapped fault.
That is a geological hypothesis, not a demonstrated result. Weathering,
lithological contacts, volcanic boundaries, alluvial-fan margins, shorelines,
roads and acquisition striping can produce similar texture without faulting.

A defensible test would specify orientation-aware window masks, valid-pixel
handling, scale and acquisition-resolution limits; pair against un-oriented and
single-layer controls; measure physical coverage and licence for the exact data;
and compare against the current shared feature stack. A 100 m raster does not
supply independent 50 m information. Cross-layer co-alignment does not prove a
fault or geothermal activity. Global novelty across sister repositories is
unverified.

The historic prototype's executed demo did **not** demonstrate a real
box-counting or directional-anisotropy pipeline: it synthesized smoothed random
fields, while the real-data path uses gradient-complexity proxies. The old
sector helper also does not apply its calculated angle to the sampled window.
Do not describe those bytes as evidence for the proposed mechanism.

Before any real test, establish an assigned lane, authentic template and inputs,
complete registry and comparable baseline; apply visible-only whole-segment
holdout, feature-by-feature leakage tests, both literal uniqueness checks and a
separate slot selector. No performance improvement is estimated here.
