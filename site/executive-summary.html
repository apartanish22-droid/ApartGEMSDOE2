Why GEMSDOE32's submission scored highest

  • -zeros suffix: values outside the study footprint are 0, removing false-positive penalty outside the area (free, legitimate score boost under Tversky/DTI).
  • h33 dotted family: dots along ridge tips / fault stepovers / blind extensions act as a recall device — with the 300 m triangular dilation kernel in pooled DTI (alpha 0.2, beta 0.8), any dot within ~300 m of a true fault counts as a hit; beta=0.8 weights false negatives heavily.
  • Blind faults: dotted tips target faults absent from the USGS/INGENIOUS catalogue (no surface scarp) — where leaderboard points live.

Verdict: 0.2778 is credible and explainable, but far below the cited 0.4413 leaderboard headroom.

Can we beat 0.2778?

Every focus-family submission is dotted-ridge / scarp / openness / catalogue-distance / Poisson dots. None combines radiometry + structural curvature on concealed faults. Our unique hypothesis H1 targets exactly that gap, is not an exact duplicate of any prior submission, and is format-safe ([0,1], single-band GeoTIFF). It is not yet scored — holdout DTI cannot be computed until real data is in data/.

New candidate hypotheses not yet tried (ranked)

1H1 Radiometric anomaly × curvature convergence GENERATED

Layers: GeoDawn radiometric (eU/eTh/K); DEM elevation.
Signature: radiometric anomaly vs local background AND curvature convergence (negative Laplacian = dilation node).
Why catalogue-missing faults: blind faults under thin cover have no scarp but altered fluids radiate radiometrically and dilate structurally.
Differs from repo/sites: first non-scarp, non-catalogue, radiometric×structural product; all GEMSDOE focus submissions are dotted/scarp/opacity/Poisson.
Expected DTI gain: High • Cost: Medium.

2Magnetic tilt-derivative lineaments + relay zones

Layers: GeoDawn aeromagnetic total field, analytic signal, tilt derivative.
Signature: potential-field edges (tilt derivative = 0) offset by stepovers/relay ramps.
Differs: potential-field edge detection is absent from all GEMSDOE focus submissions.
Gain: Medium-High • Cost: Medium.

3Multi-directional DEM lineament intersection density

Layers: DEM hillshade; 4-direction edge filters.
Signature: X-junctions of orthogonal lineaments = fault relay/stepover nodes.
Differs: prior work uses single-direction openness/scarp.
Gain: Medium • Cost: Low.

4Catalogue distance-decay × DEM aspect (thermal proxy)

Layers: USGS/INGENIOUS faults; DEM aspect.
Signature: exponential distance decay from mapped faults gated on warm-facing aspect.
Differs: catalogue-based like h33 dots, but adds aspect gate.
Gain: Low-Medium • Cost: Low.

5Radiometric K/(K+Th) alteration index alone

Layers: GeoDawn K, Th bands.
Signature: potassium enrichment relative to thorium (hydrothermal illitization halo).
Differs: single-band ratio — simpler than H1; good leakage-canary control.
Gain: Low • Cost: Low.

Recommended first experiment (once data exists): validate H1 on the spatially-blocked holdout; submit only if holdout DTI + 95% CI beats the current best (protocol budget: ≤3 experiments / ≤2 hours).

Generate & submit — step by step

  1. Download data (authenticated machine): bash scripts/download_competition_data.sh → place data/numeric_features.tif, data/labels.tif, data/example_submission.tif in the repo.
  2. Validate grid: python scripts/prepare_data.py → writes data/grid_reference.json.
  3. Generate unique submission: python src/generate_submission.py → writes a unique assets/gems-h1-*.tif (+ stable assets/submission.tif).
  4. Validate before submitting: python src/validate_submission.py assets/<name>.tif → all gates PASS (single band GTiff, CRS/shape/transform match, no NaN inside footprint, values in [0,1]).
  5. Holdout gate (mandatory): run src/evaluate_holdout.py; spend a weekly submission slot only if holdout DTI + 95% CI beats the current best.
  6. Submit on DrivenData: single-band GeoTIFF (.tif) or .zip of one; unique name; short note (≤140 chars); values in [0,1]; CRS/shape/geotransform must match the submission format.

Error fix: the submission-form error "Predicted values must be in range [0, 1]" is prevented by construction — src/submission_writer.py clips all values to [0,1] before writing.
